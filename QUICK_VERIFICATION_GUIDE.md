# Quick Verification Guide

## TL;DR

To verify that the CLI refactoring produces identical outputs:

```bash
make verify-e2e-outputs
```

## What This Does

Runs 8 comprehensive E2E tests to verify that:
- `--multiple-by-type` mode produces the same test case outputs as before
- `--single` mode produces the same container outputs as before
- All generated files match the expected output files

## When to Run This

- ✅ After making changes to the CLI argument parsing
- ✅ After modifying template rendering logic
- ✅ Before submitting a PR for the CLI refactoring
- ✅ When reviewing the refactoring branch
- ✅ As part of CI/CD validation

## What Success Looks Like

```
All tests passed! ✓

The output files generated by the new CLI interface (--single and --multiple-by-type)
match the expected output files, confirming that the refactoring maintains
the same behavior as the original --container and --test-case modes.
```

## What Failure Looks Like

If tests fail, you'll see:
- Which test failed
- The diff between expected and actual output
- Location of detailed logs in `.tmp/verify-e2e-*/`

## CLI Interface Comparison

### Old Way (main branch)
```bash
tpdg --container schema.json template.j2 data.yml \
     --test-case verification_methods/ test1.yml test2.yml
```

### New Way (this branch)
```bash
# Step 1: Generate test cases
tpdg --multiple-by-type .type verification_methods/ test1.yml test2.yml

# Step 2: Render container
tpdg --single schema.json template.j2 data.yml
```

## Files Created

The verification script creates these actual output files:
- `data/output.actual.md`
- `data/test_plan_output.actual.adoc`
- `data/test_results_output.actual.adoc`
- `data/test_results_output.actual.md`
- `data/input_data/output.actual.md`
- `data/input_data/test_plan_output.actual.adoc`
- `data/input_data/test_results_output.actual.adoc`
- `data/input_data/test_results_output.actual.md`

These are compared against the corresponding `.expected.*` files.
