# E2E Output Verification Script

## Purpose

This script (`verify_e2e_outputs.sh`) verifies that the output files generated by the E2E tests in the `refactor-cli-single-multiple-modes` branch match the expected output files. This ensures that the CLI refactoring from the old `--container` and `--test-case` modes to the new `--single` and `--multiple-by-type` modes produces identical outputs.

## What It Does

The script:

1. **Builds the project** using `cargo build --release`
2. **Runs 8 comprehensive E2E tests** that cover all output scenarios:
   - Markdown output
   - AsciiDoc test plan output
   - AsciiDoc test results output
   - Markdown test results output
   - Input data markdown output
   - Input data AsciiDoc test plan
   - Input data AsciiDoc test results
   - Input data markdown test results

3. **For each test**:
   - Generates test cases using `--multiple-by-type` mode
   - Processes the test cases (applies sed/perl transformations)
   - Renders the container template using `--single` mode
   - Compares the actual output with the expected output file
   - Reports success or failure with detailed diffs

4. **Provides a summary** of all passed and failed tests

## Usage

```bash
# Run from the project root
./scripts/verify_e2e_outputs.sh

# Or using make (if a target is added)
make verify-e2e-outputs
```

## Expected Behavior

When the refactoring is correct, all tests should pass, indicating that:
- The `--multiple-by-type` mode produces the same test case outputs as the old mode
- The `--single` mode produces the same container outputs as the old mode
- All expected output files match the actual generated files

## Test Coverage

The script tests the following output files:

1. `data/output.actual.md` vs `data/output.expected.md`
2. `data/test_plan_output.actual.adoc` vs `data/test_plan_output.expected.adoc`
3. `data/test_results_output.actual.adoc` vs `data/test_results_output.expected.adoc`
4. `data/test_results_output.actual.md` vs `data/test_results_output.expected.md`
5. `data/input_data/output.actual.md` vs `data/input_data/output.expected.md`
6. `data/input_data/test_plan_output.actual.adoc` vs `data/input_data/test_plan_output.expected.adoc`
7. `data/input_data/test_results_output.actual.adoc` vs `data/input_data/test_results_output.expected.adoc`
8. `data/input_data/test_results_output.actual.md` vs `data/input_data/test_results_output.expected.md`

## Output

The script outputs:
- Progress messages for each test
- Success/failure indicators (✓/✗)
- Diffs for any failed tests (first 50 lines)
- A final summary with counts of passed and failed tests

## Exit Codes

- `0`: All tests passed
- `1`: One or more tests failed

## Troubleshooting

If tests fail:
1. Check the diff output to see what changed
2. Review the temporary directories in `.tmp/verify-e2e-*` for detailed logs
3. Verify that the CLI implementation matches the expected behavior
4. If the new behavior is correct, update the expected output files

## Relationship to Makefile E2E Tests

This script mirrors the logic in the Makefile's E2E test targets (`test-e2e-markdown`, `test-e2e-test-plan-asciidoc`, etc.) but uses the new CLI interface (`--single` and `--multiple-by-type`) instead of the old interface (`--container` and `--test-case`).

The script helps verify that the CLI refactoring maintains backward compatibility in terms of output while changing the invocation interface.
